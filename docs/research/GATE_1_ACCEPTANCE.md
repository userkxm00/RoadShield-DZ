# RoadShield DZ — Gate 1 Acceptance Criteria

## Gate
**Gate 1 — Research & Innovation Definition**

## Required before Gate 1 can close
- [x] Problem is defined without unsupported causal claims.
- [x] Official Algerian road-safety context is documented.
- [x] SNAR boundary is documented.
- [x] Waze hazard-reporting overlap is documented.
- [x] RoadShield is explicitly not positioned as a navigation or accident-reporting clone.
- [x] Innovation thesis is defined as an evidence/corroboration pipeline rather than simple pothole detection.
- [x] IP hypotheses are documented as hypotheses, not as granted rights.
- [x] MVP scope and non-goals are explicit.
- [x] Experimental hypotheses are explicit and falsifiable.
- [x] MVP success criteria are measurable.
- [ ] Founder/user validation interviews completed.
- [ ] Controlled sensor feasibility experiment completed.
- [ ] Competitor claims have been reviewed for current accuracy immediately before competition submission.

## Current status
**Research definition: substantially complete. External validation remains open.**

Gate 1 must not be marked fully closed until at least a small controlled sensor feasibility test and a short set of user/stakeholder discovery interviews are completed, because these cannot be honestly inferred from desk research alone.

## Owner decision required
Before implementation begins, the repository owner should explicitly approve:
